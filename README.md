# אתגר 14 ימים: הוראות הפעלה

אפליקציית PWA לאתגר קבוצתי של 7 משתתפים, 14 ימים, 5 כללים יומיים.
אתר סטטי שמתארח ב-GitHub Pages. הסימונים נשמרים בגיליון Google Sheets דרך Apps Script.

- כתובת האתר: https://ellieelkon-dotcom.github.io/challenge/
- הגיליון: https://docs.google.com/spreadsheets/d/1agPKSKqG9gPmEyRe1flu2TTQ2wsQg7jIfx2eCLKb8Iw/edit

## האתגר

- התחלה 2026-11-29 (יום ראשון), סיום 2026-12-12.
- משתתפים: אלי, רון, ליאל, נועה, איתי, ורד, קובי.
- כללים: 10,000 צעדים; אימון 40 עד 60 דקות; בלי סוכר מעובד; 3 ליטר מים; 10 דקות קריאה.
- יום מושלם: כל 5 הכללים סומנו. ניקוד מלא: 70 סימונים.

## 1. הסקריפט בגיליון (פעם אחת)

1. פותחים את הגיליון ובוחרים Extensions, ואז Apps Script.
2. מוחקים את הקוד שיש שם ומדביקים את כל התוכן של `apps-script/Code.gs`. שומרים.
3. לוחצים Deploy, ואז New deployment, ובוחרים Web app.
4. בהגדרות: Execute as = Me, Who has access = Anyone. לוחצים Deploy ומאשרים את ההרשאות.
   אם מופיעה אזהרת "Google hasn't verified this app": Advanced, ואז Go to ... (unsafe).
5. מעתיקים את הכתובת שמסתיימת ב-`/exec`.

הסקריפט יוצר לבד שתי לשוניות:
- "נתונים": שם, תאריך, מסכה, עודכן. שורה אחת לכל משתתף לכל יום.
- "יומן": זמן, שם, תאריך, כלל, מצב. שורה לכל שינוי, וממנה מורכב פיד הפעילות.

עמודות השם והתאריך מוגדרות כטקסט, כדי ש-Sheets לא יהפוך תאריכים ל-Date.

### עדכון הסקריפט אחרי שינוי בקוד

כדי לשמור על אותה כתובת `/exec`: Deploy, ואז Manage deployments, בוחרים את
הפריסה הקיימת, לוחצים על אייקון העיפרון, ב-Version בוחרים New version, ו-Deploy.
פריסה חדשה (New deployment) תיצור כתובת אחרת ותחייב עדכון של `config.js`.

## 2. הכתובת באפליקציה

בקובץ `config.js` מדביקים את הכתובת בין המרכאות של `API_URL`, ודוחפים ל-main.
כל עוד `API_URL` ריק, האפליקציה עובדת במצב ניסיון: הסימונים נשמרים רק בטלפון.

## 3. GitHub Pages

Settings, ואז Pages: Source = Deploy from a branch, Branch = main, תיקייה = / (root).
אחרי דקה או שתיים האתר זמין בכתובת שלמעלה.

## 4. התקנה בטלפון

כל אחד פותח את הקישור, בוחר את השם שלו, ומוסיף למסך הבית.
- אייפון, בספארי: כפתור השיתוף, ואז הוספה למסך הבית.
- אנדרואיד, בכרום: תפריט שלוש הנקודות, ואז התקנת אפליקציה.

## מבנה

| קובץ | תפקיד |
| --- | --- |
| `index.html` | מבנה ועיצוב (CSS פנימי), עברית RTL, בהיר וכהה לפי המערכת |
| `app.js` | כל הלוגיקה: בחירת שם, סימון, תור שליחה, סנכרון, חישוב ניקוד, פיד פעילות |
| `config.js` | START, DAYS, PEOPLE, RULES, API_URL |
| `sw.js` | service worker: רשת קודם, ואם אין קליטה מהמטמון |
| `manifest.webmanifest` | הגדרות PWA |
| `apps-script/Code.gs` | doGet ו-doPost עם upsert, יומן שינויים ו-LockService |
| `tests/smoke.mjs` | בדיקת עשן ב-jsdom |

## בדיקות

```bash
node --check app.js && node --check config.js && node --check sw.js
npm install jsdom
node tests/smoke.mjs
```

הבדיקה מריצה את האפליקציה ב-jsdom עם תאריך מדומה ושרת מדומה: בחירת שם, סימון,
שליחה ל-API, תור במצב לא מחובר, משיכת נתונים ב-focus, וחישוב ניקוד ורצף.
יש לשים את `node_modules` מחוץ לריפו או להוסיף אותו ל-`.gitignore`.

## הערות

- שמות המשתתפים צריכים להיות זהים ב-`config.js` (PEOPLE) וב-`Code.gs` (PEOPLE). אם משנים, משנים בשניהם.
- אין התחברות. הריפו ציבורי, ולכן כתובת הסקריפט גלויה. מי שמוצא אותה יכול לסמן במקום אחרים.
  בין חברים זה בסדר, אבל זו לא הגנה.
- הנתונים נשמרים בלשוניות "נתונים" ו"יומן". הלשוניות הישנות בגיליון (סיכום, אלי, רון, איתי) לא מתעדכנות.
- פיד הפעילות מציג את 12 השינויים האחרונים. `doGet` מחזיר עד 40, וזה נשלט ב-`LOG_LIMIT` ב-`Code.gs`.
- העיצוב: צהוב שמש ולילך עמוק, Suez One לכותרות ו-Rubik לגוף, וחמישה צבעים קבועים לחמשת הכללים
  (כחול לצעדים, ורוד לאימון, כתום לסוכר, טורקיז למים, סגול לקריאה). הצבעים חוזרים בפס הימים,
  בנקודות של לוח הקבוצה ובפיד, כדי שאפשר יהיה לזהות כלל לפי צבע בלי לקרוא.
- `doPost` שולח Content-Type של text/plain בכוונה, כדי לא לעורר preflight של CORS.
